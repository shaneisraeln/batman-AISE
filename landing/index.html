The problem

A model exposed through an API can be probed one valid request at a time. Traditional API security sees each call in isolation — it can catch malformed payloads, failed auth, and raw request floods, but it does not understand whether a sequence of otherwise-valid ML queries is suspicious from the model's perspective.

↯

API abuse

High-rate, bursty, and repeated queries that strain the model.

◎

Model extraction

High-volume, high-diversity queries that systematically harvest the model's behavior.

⚠

Anomalous inputs

Out-of-range values, extreme norms, and distribution shifts.

How BATMAN works

BATMAN sits in front of your model as a security gateway. It analyzes behavior across requests within a session, decides an action with a deterministic policy engine, and only then lets an allowed request reach your model. 

Client
  ↓
BATMAN Gateway   ── authenticate · validate · rate-limit
  ↓
Behavioral features (per session)
  ↓
Detection        ── rules + Isolation Forest + extraction signals
  ↓
Agents           ── investigate (RAG + LLM explanation, advisory)
  ↓
Policy Engine    ── AUTHORITATIVE
  ↓
ALLOW · RATE_LIMIT · BLOCK
  ↓
Your ML model (only if allowed)  →  Telemetry  →  Dashboard

The policy engine is authoritative. The LLM explains and recommends — it never overrides an enforcement decision.

Behavioral detection

Learns normal, flags deviation

An Isolation Forest is calibrated on your service's own normal traffic. A dedicated detector scores model-extraction and probing behavior from request rate, query diversity, and systematic input variation.

Deterministic floor

Rules and rate limiting stay active even if the ML detector, RAG, or LLM are unavailable. Security enforcement never depends on the language model.

Validation note: in controlled development testing against a real deployed model, the behavioral detector reached an F1 around 0.89 on extraction and anomalous-input detection and generalized to an unseen extraction strategy (F1 ≈ 0.94). These are development results on controlled traffic, not a guarantee for every workload — thresholds must be calibrated per model.

Two ways to integrate

Python SDK

Route inference through BATMAN with a lightweight client.

pip install batman-ml
from batman_ml import protect

protected = protect(
    api_key="bm_live_xxxxx",
    base_url="https://your-batman.example",
)
prediction = protected.predict(X)

REST / Gateway

Already have a deployed model API? Register its endpoint and let BATMAN proxy to it — no retraining, no model change. 

curl -X POST https://your-batman.example/v1/predict \
  -H "x-api-key: bm_live_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{"inputs": [[/* features */]]}'

Monitoring & feedback

Every request produces structured, request-traceable telemetry. The dashboard shows real traffic, threat categories, latency, and per-model activity — with controlled security tests clearly labelled, never mixed with production traffic. Analysts can label detections to inform future evaluation.

What BATMAN does not claim

Security is about reducing risk, not eliminating it. BATMAN is a behavioral runtime layer for ML inference — it is deliberately honest about its scope.

  • It does not protect against every cyberattack.
  • It does not guarantee perfect detection or zero false positives.
  • It does not replace a WAF, SIEM, IAM, or your infrastructure security.
  • It does not guarantee detection of every adversarial example.
  • Detection thresholds must be calibrated against your model's own traffic.
