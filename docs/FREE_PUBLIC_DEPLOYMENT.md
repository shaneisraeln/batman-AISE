# BATMAN — Free Public Deployment (step-by-step for the owner)

This is the exact procedure to put BATMAN online at **₹0** using **Vercel**
(frontend) + **Render Free** (FastAPI) + **Neon Free** (PostgreSQL).

Legend:
- `MANUAL ACTION` = you do it in a browser (account/auth/DB creation).
- Everything else is a copy-paste command.
- Placeholders like `<render-url>` are filled in as you go.

Run all commands from the repo root (`e:\Hackathons\BATMAN`) unless noted.

## 3. PostgreSQL — Neon (chosen; see docs/FREE_DEPLOYMENT_PLAN.md for why)

**Why Neon:** free, persistent (no expiry), SSL, remote connections, no card.
Render's own free Postgres is rejected because it is **deleted after 30 days**.

`MANUAL ACTION`:
1. Go to https://neon.tech → sign up (GitHub login is fine).
2. Create a project (any name, e.g. `batman`). Pick a region near your Render region.
3. In the project dashboard, open **Connection Details** → copy the
   **connection string**. It looks like:
   ```
   postgresql://USER:PASSWORD@ep-xxxx-xxxx.REGION.aws.neon.tech/DBNAME?sslmode=require
   ```
4. **Copy** that whole string. You will paste it into Render as
   `BATMAN_DATABASE_URL` in step 5.

Do **NOT** put this string in Git, `.env` committed to Git, source, the
frontend, or any doc. It lives only in Render's environment settings.

## 4. Render — create the backend service

`MANUAL ACTION`:
1. Go to https://render.com → sign up (GitHub login).
2. **New → Blueprint** → connect your GitHub → pick the `batman-AISE` repo.
   Render reads `render.yaml` and proposes a web service named `batman-api`
   (Docker, free plan, health check `/v1/health`).
   - If Blueprint isn't offered: **New → Web Service** → select the repo →
     choose **Docker** runtime → Dockerfile path `./Dockerfile.cloud` → plan
     **Free**.
3. Click **Apply / Create**. Do **not** deploy yet if it lets you set env first;
   otherwise the first build will fail on the missing DB URL — that's fine,
   you'll add env vars next and redeploy.

## 5. Render — environment variables

`MANUAL ACTION` — in the `batman-api` service → **Environment** → add
(full reference: docs/RENDER_ENVIRONMENT.md):

| Variable | Value |
|---|---|
| `BATMAN_DATABASE_URL` | the Neon string from step 3 |
| `BATMAN_ENCRYPTION_KEY` | generate locally (below), paste it |
| `BATMAN_CORS_ORIGINS` | leave blank for now; set in step 11 after Vercel |
| `BATMAN_SECRET_KEY` | auto-generated by Render (from render.yaml) — leave it |

Generate the Fernet encryption key locally and copy the output:
```powershell
.\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

The non-secret vars (`BATMAN_ENV=production`, `BATMAN_MODE=enforce`,
`BATMAN_DETECTOR_PATH`, `BATMAN_LLM_PROVIDER=stub`,
`BATMAN_ALLOW_PRIVATE_UPSTREAM=0`) come from `render.yaml` automatically.

## 7. Verify the backend

```powershell
curl https://<render-url>/v1/health
```
Expect: `{"status":"ok","mode":"enforce","detector_ready":true,"llm_provider":"stub"}`

Prove the database works (signup → login → me):
```powershell
curl -X POST https://<render-url>/auth/signup -H "Content-Type: application/json" -d "{\"email\":\"you@example.com\",\"password\":\"password123\"}"
```
Copy the `token` from the response, then:
```powershell
curl https://<render-url>/auth/me -H "Authorization: Bearer <token>"
```
Expect your user object. If this works, Render is talking to Neon Postgres.

Open `https://<vercel-url>` and run the funnel:

2. Create a project.
3. Register a model.
4. Generate an API key (copy it — shown once).

localhost) and succeeding (no CORS errors).

## 15. Troubleshooting

- **CORS error in browser console** → `BATMAN_CORS_ORIGINS` on Render doesn't
  exactly match `<vercel-url>` (scheme + host, no trailing slash). Fix + redeploy.
- **First request hangs ~1 min** → Render free cold start after 15 min idle.
  Normal; retry. Keep-alive pingers exist but aren't required for MVP.
- **`500`/`RuntimeError: psycopg not installed`** → you deployed a non-cloud
  build. The Docker image installs `.[cloud]`; make sure Render uses
  `Dockerfile.cloud` (it does via `render.yaml`).
- **DB connection / SSL error** → the Neon URL must end with `?sslmode=require`
  (Neon's copied string already does). Re-copy it exactly.
- **`401` on every call** → missing/expired Bearer token; log in again. Or the
  frontend built without `VITE_API_BASE` (calls hit Vercel instead of Render).
- **`403` on predict** → BATMAN blocked it (policy) — expected for attack
  traffic. Not an error.
- **`429`** → rate limited (per-key or control-plane). Expected under bursts.
- **`400 upstream_url_...` when setting upstream** → SSRF guard rejected a
  private/loopback/non-https URL. Use a public HTTPS model endpoint (or set
  `BATMAN_ALLOW_PRIVATE_UPSTREAM=1` only if the model is on a trusted private net).
- **`502 upstream_error`** → your protected model API failed or was unreachable;
  distinct from a BATMAN block.
- **Vercel build fails** → ensure you ran `vercel` from the `dashboard/` dir
  (root = dashboard). Framework preset should be Vite.
- **Render build fails** → check the build log; usually a transient dep download.
  Redeploy. The detector-training step needs the `training/` + `attacks/` dirs
  (they're in the repo).
